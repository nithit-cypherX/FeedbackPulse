# P02-T03 — เพดานความยาวข้อความ

- Task: [P02-T03 ใน phase plan](../docs/plans/P02-model-pipeline.md) · ข้อตกลงที่อัปเดต: [P01-T02 §7](../docs/plans/P01-T02-api-contract.md#7-จุดที่ยังต้องยืนยันและการส่งต่องาน)
- รันเมื่อ: 2026-10-07 · model revision `3216a57f2a0d9c45a2e6c20157c20c49fb4bf9c7` (ดู [P02-T01](P02-T01-model-provenance.md))
- เครื่อง: macOS 15.5 arm64 · Python 3.13.11 · `torch 2.14.1` · `transformers 5.19.0`

## 1. ตรวจอะไร

[P01-T02 §7](../docs/plans/P01-T02-api-contract.md#7-จุดที่ยังต้องยืนยันและการส่งต่องาน) สั่งให้ P02 ตรวจ tokenizer ของ revision ที่ใช้จริง แล้วบันทึก 3 อย่าง: **ค่าที่รองรับ**, **วิธีนับ** และ **การรวม special tokens** · พร้อมยืนยันพฤติกรรมที่ตกลงไว้ว่า ยาวเกินแล้ว **ปฏิเสธ ไม่ตัดเงียบ ๆ**

## 2. ใช้รุ่นและเงื่อนไขไหน

ใช้ tokenizer และ model จาก revision ที่ pin ใน P02-T01 เท่านั้น · ไม่ใช้ dataset จาก P02-T02 ทดสอบ เพราะข้อความในนั้นยาวสุด **186 อักขระ** ซึ่งไม่แตะเพดาน จึงสร้างข้อความทดสอบขึ้นเอง

**ทำไมอ่าน `tokenizer.model_max_length` ไม่ได้:** repo ของ model **ไม่มี `tokenizer_config.json`** ทำให้ค่านี้คืน sentinel `1000000000000000019884624838656` ซึ่งไม่ใช่เพดานจริง (บันทึกไว้ใน [P02-T01 §5](P02-T01-model-provenance.md)) · จึงต้องหาเพดานจาก `config.json` ประกอบกับการทดลอง

## 3. คาดหวังอะไร

`config.json` ระบุ `max_position_embeddings = 514` · RoBERTa ใช้ตำแหน่งสำรอง 2 ช่องจาก `pad_token_id = 1` จึงคาดว่าความยาวลำดับที่ใช้ได้จริงคือ 512 · ต้องยืนยันด้วยการรัน ไม่ใช่สรุปจากตัวเลขนี้อย่างเดียว

## 4. ได้ผลอะไร

### Special tokens

tokenizer เติม **2 tokens** ให้ทุกข้อความ: `<s>` ข้างหน้าและ `</s>` ข้างหลัง

```
"hello" -> input_ids [0, 42891, 2] -> ['<s>', 'hello', '</s>']
tok.num_special_tokens_to_add(pair=False) == 2
```

### เพดานที่วัดได้

ทดลอง forward ด้วยความยาวลำดับรวมหลายค่า:

| total tokens (รวม special) | ผล |
|---:|---|
| 510 | ผ่าน |
| 511 | ผ่าน |
| **512** | **ผ่าน — ค่าสูงสุดที่ใช้ได้** |
| 513 | พัง `RuntimeError: index 514 is out of bounds for dimension 1 with size 514` |
| 514 | พัง (ข้อผิดพลาดเดียวกัน) |

ยืนยันซ้ำด้วย **ข้อความจริงผ่าน tokenizer** ไม่ใช่สร้าง `input_ids` เอง:

| กรณี | อักขระ | total tokens | content tokens | forward |
|---|---:|---:|---:|---|
| ที่เพดาน | 1,527 | 512 | 510 | ผ่าน |
| เกินเพดาน 1 token | 1,530 | 513 | 511 | พัง `RuntimeError` เดิม |

### ค่าที่ล็อก

| รายการ | ค่า |
|---|---|
| **ความยาวลำดับรวมสูงสุด** | **512 tokens** |
| **จำนวน special tokens ที่นับรวม** | **2** (`<s>` + `</s>`) |
| **เนื้อหาข้อความสูงสุด** | **510 tokens** |
| **วิธีนับ** | นับ **token** ด้วย tokenizer ของ revision ที่ pin ไว้ **ไม่ใช่นับอักขระ** |

### tokenizer ไม่ตัดให้เอง ถ้าไม่สั่ง

| การเรียก | ผลกับข้อความ 513 tokens |
|---|---|
| `tok(text)` | คืน 513 — **ไม่ตัด** รายงานความยาวจริง |
| `tok(text, truncation=True, max_length=512)` | คืน 512 — **ตัดจริง** |

`truncation=True` ทำสิ่งที่ P01-T02 §3 ห้ามไว้ (“ไม่ตัดส่วนท้ายทิ้งเงียบ ๆ”) → **โค้ดของเราต้องไม่ใช้ `truncation=True`** ต้องนับแล้วปฏิเสธ

## 5. มีข้อจำกัดอะไร และส่งต่ออะไร

### ส่งต่อให้ P03 — ต้องตรวจก่อนเรียก model

ถ้าส่งข้อความ 513 tokens เข้า model ผลที่ได้คือ **`RuntimeError` ไม่ใช่ข้อผิดพลาดที่สื่อความ** · ถ้า API ไม่ตรวจก่อน ข้อความยาวเกินจะกลายเป็น `500` ซึ่งขัดกับ [P01-T02 §4](../docs/plans/P01-T02-api-contract.md#4-validation-และ-error-handling) ที่กำหนดให้เป็น **`422`** → **P03 ต้องนับ token แล้วปฏิเสธก่อนเรียก model**

### ส่งต่อให้ P03 — นับอักขระแทน token ไม่ได้

อัตราอักขระต่อ token ไม่คงที่ วัดได้:

| ข้อความ | อักขระ | tokens | อักขระ/token |
|---|---:|---:|---:|
| คำสั้นซ้ำ (`"ok "`) | 1,530 | 513 | 2.98 |
| ตัวอักษรเดียวติดกัน (`"a"*2000`) | 2,000 | 502 | 3.98 |
| ภาษาไทย | 1,300 | 2,502 | **0.52** |

ภาษาไทยให้ token **มากกว่า**จำนวนอักขระ ดังนั้นเพดานแบบนับอักขระที่ตั้งจากกรณีภาษาอังกฤษ (เช่น 1,527 อักขระ) จะ **ปล่อยข้อความที่เกิน 512 tokens ผ่านไปได้** · ขอบเขตโครงการรับเฉพาะภาษาอังกฤษ แต่ไม่มีอะไรห้ามผู้เรียกส่งภาษาอื่นมา

**ข้อเสนอให้ P03 พิจารณา ไม่ใช่ข้อตกลงที่ล็อกแล้ว:** ใช้การนับ token เป็นเกณฑ์ตัดสิน `422` และถ้าต้องการกันคำขอขนาดใหญ่ไม่ให้เสียเวลา tokenize อาจเพิ่มเพดานขนาด request แยกอีกชั้น · การตั้งค่านั้นเป็นการตัดสินใจของ P03 รายงานนี้ไม่ได้ล็อกให้

### ข้อจำกัดอื่น

- ค่าทั้งหมดผูกกับ revision `3216a57f…` **ถ้าเปลี่ยน revision ต้องรัน T03 ใหม่** เพราะ `max_position_embeddings` และ tokenizer อาจต่างไป
- ยังไม่ได้วัดว่าข้อความที่ 510 content tokens ใช้เวลา inference เท่าไร — การวัด latency เป็นงาน T09 และ P03–P04
- การตรวจ boundary case ผ่าน API จริง (`422` และไม่ตัดแล้วทำนายต่อ) ยังทำไม่ได้เพราะยังไม่มี API — อยู่ใน checklist ของ P03
